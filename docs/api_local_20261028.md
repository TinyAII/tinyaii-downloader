# 本地 API 与 MCP 接口说明

> 更新于 2026-10-28。对应客户端版本 1.0.0。
> 本文只描述**已经实现并实测过**的接口；没做的都写在最后一节，别照着猜。

---

## 1. 基本信息

| 项 | 值 |
|---|---|
| 监听地址 | `http://127.0.0.1:17890`（**只绑本机**，端口固定不可配） |
| **开关** | **默认关闭**。客户端「本地 API」页面右上角切换，状态存 `%APPDATA%\com.xiaojie.tauri-app\api-enabled`（`1` 开 / `0` 关）。关闭后端口不监听，外部连接会被直接拒绝 |
| 鉴权 | 请求头 `X-Api-Token: <token>`，所有接口都要 |
| Token 位置 | `%APPDATA%\com.xiaojie.tauri-app\api-token` |
| Token 规则 | 32 位十六进制，首次启动生成，重启不变；删掉该文件再启动即换新 |
| 返回格式 | 除 MCP 外都是 JSON；成功 `{"ok":true,...}`，失败见下 |

失败响应：

```json
{"ok":false,"error":{"code":"unknown_field","message":"请求体解析失败: unknown field `foo`, ..."}}
```

### 错误码

| code | HTTP | 含义 |
|---|---|---|
| `unauthorized` | 401 | 缺 token 或 token 不对 |
| `bad_request` | 400 | 请求头/行不合法、过大 |
| `invalid_json` | 400 | 请求体不是合法 JSON，或字段类型不对 |
| `unknown_field` | 400 | 传了不认识的字段（message 里会列出全部可用字段） |
| `invalid_request` | 400 | 字段合法但值不成立（例如 links 为空） |
| `create_failed` | 400 | 建任务被拒（路径/参数校验失败） |
| `not_found` | 404 | 接口不存在 |
| `mirror_not_found` | 400 | 指定了不存在的 GitHub 加速项（message 里列出可用项） |
| `task_not_found` | 404 | gid 不存在 |
| `engine_unavailable` | 502 | 连不上 aria2 引擎 |
| `engine_error` | 502 | aria2 执行出错（message 里带原始错误） |
| `state_error` | 500 | 服务内部状态异常（正常不会遇到） |

## 2. 端点总表

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/ping` | 服务与引擎状态 |
| GET | `/api/v1/tasks` | 任务列表 |
| GET | `/api/v1/tasks/{gid}` | 单个任务 |
| POST | `/api/v1/tasks` | 新建任务（仅直链） |
| POST | `/api/v1/tasks/{gid}/pause` | 暂停 |
| POST | `/api/v1/tasks/{gid}/resume` | 继续 |
| POST | `/api/v1/tasks/{gid}/remove` | 删除任务记录（**不删磁盘文件**） |
| GET | `/api/v1/config` | 引擎配置快照（只读） |
| POST | `/api/v1/config/speed` | 设置全局限速 |
| POST | `/mcp` | MCP JSON-RPC（同端口，见第 8 节） |

`{gid}` 前后空白会被自动去掉。

## 3. 新建任务 `POST /api/v1/tasks`

### 字段表

| 字段 | 别名 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| `links` | `url` `urls` `link` | 字符串数组 **或单个字符串** | 必填 | 直链。**不支持网盘分享链接**，需要先在客户端里解析 |
| `savePath` | `dir` `path` `dst` `out` | 字符串 | `%USERPROFILE%\Downloads` | 保存目录，不存在会创建 |
| `rename` | `name` `filename` | 字符串 | 空 | 多链接时自动加 `-1` `-2` 后缀 |
| `splitCount` | `split` | 整数 | `128` | 分片数，服务端会做范围约束 |
| `maxConnectionsPerServer` | — | 整数 | `64` | 单服务器连接数 |
| `maxDownloadLimit` | `maxDownloadSpeed` | 整数 | `0` | **字节/秒**，0 = 不限 |
| `maxUploadLimit` | `maxUploadSpeed` | 整数 | `0` | **字节/秒**，0 = 不限 |
| `lowestSpeedLimit` | — | 整数 | `0` | 字节/秒。低于此速度 aria2 会判定失败（用来避免慢速磨到底），0 = 不启用 |
| `checksum` | — | 字符串 | 空 | 形如 `sha-256=<hex>`。**校验失败任务会被标记 failed，errorCode=32** |
| `userAgent` | — | 字符串 | 空 | |
| `authorization` | — | 字符串 | 空 | 会拼成 `Authorization` 头 |
| `referer` | — | 字符串 | 空 | |
| `cookie` | — | 字符串 | 空 | |
| `proxy` | — | 字符串 | 空 | aria2 `all-proxy` 格式 |
| `githubMirrorId` | — | 字符串 | 不传 | 用 `GET /config` 里 `mirrors.list[].id` 指定加速项，**仅本次任务** |
| `githubMirror` | — | 字符串 | 不传 | 直接给加速前缀；**传空串表示本次强制直连**。与 `githubMirrorId` 同时存在时以它为准 |

**未知字段一律 400**（不会静默忽略）。返回的 message 里会列出所有可用字段名。

### 示例

```bash
curl -X POST http://127.0.0.1:17890/api/v1/tasks \
  -H "X-Api-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/big.iso",
    "dir": "D:/下载",
    "maxDownloadLimit": 2097152,
    "checksum": "sha-256=9f86d0818...（64位hex）"
  }'
```

响应：

```json
{"ok":true,"count":1,"tasks":[{"id":"964b617483439afd","status":"downloading",...}]}
```

## 4. 任务对象

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | aria2 的 gid |
| `name` | string | 文件名（BT 用种子里的名字，直链取路径末段） |
| `status` | string | 见第 5 节 |
| `url` | string | 原始链接 |
| `savePath` | string | 保存目录 |
| `totalBytes` / `downloadedBytes` | number | 总长 / 已完成 |
| `speedBytes` / `uploadSpeedBytes` | number | 当前速度（字节/秒） |
| `connections` | number | 当前连接数 |
| `splitCount` | number | 分片数 |
| `pieceLength` / `bitfield` | number / string | 分片信息 |
| `errorCode` / `errorMessage` | string | 失败时才有值；`errorCode=32` 是校验不通过 |
| `createdAt` | number | 毫秒时间戳，**语义见第 6 节** |
| `completedAt` | number \| null | 同上 |
| `files` | 数组 | `index / path / length / completedLength / selected` |

---

## 5. 状态机

实际会出现 6 种值：

| status | 含义 | 会不会自己变 |
|---|---|---|
| `downloading` | 下载中 | 会 |
| `seeding` | BT 做种中 | 会 |
| `paused` | 已暂停 | 不会 |
| `completed` | 已完成 | 不会 |
| `failed` | 失败（看 `errorCode` / `errorMessage`） | 不会 |
| `stopped` | 已停止或已移除 | 不会 |

`stopped` 是个混合态：aria2 的 `removed` 和 `stopped` 都映射到它。判断“到底是失败还是被停掉”，看 `errorCode`：空字符串 = 没有错误。

---

## 6. 时间字段的真相（重要）

`createdAt` / `completedAt` **不是 aria2 给的**——aria2 不提供这两个时间。实现方式是服务端在第一次观察到该任务时记一笔：

- `createdAt` = 第一次看到这个 gid 的时间
- `completedAt` = 第一次看到它 `completed` 的时间
- 误差 = 一次轮询间隔
- **只存在内存里，重启丢失**：应用重启后，aria2 里遗留的旧任务会被重新计时

所以：**别拿它做精确计费或统计**，只能用来做“大概什么时候下的”和列表排序。

## 7. 限速与配置

### 每任务（见第 3 节字段表）
`maxDownloadLimit` / `maxUploadLimit` / `lowestSpeedLimit` 直接写进 aria2 任务选项，互不影响。

### 全局

`GET /api/v1/config` → 只读快照：

```json
{"ok":true,"config":{
  "downloadDir":"C:\\Users\\xxx\\Downloads",
  "maxOverallDownloadLimit":"0",
  "maxOverallUploadLimit":"0",
  "lowestSpeedLimit":"0",
  "maxConcurrentDownloads":"16"
}}
```

### GitHub 加速（`mirrors`）

`GET /api/v1/config` 的顶层多一个 `mirrors`：

```json
"mirrors":{
  "activeId":"direct",
  "list":[
    {"id":"direct","label":"直连 GitHub","prefix":""},
    {"id":"ghproxy","label":"gh-proxy.com","prefix":"https://gh-proxy.com/"}
  ]
}
```

- `activeId` 是客户端设置里当前选中的项
- `list` 是客户端配置的完整列表，由客户端在设置变更时推送；API **不修改**它，只能读
- 建任务时不传 `githubMirrorId` / `githubMirror` → 沿用 `activeId`（与界面行为一致）
- 只对 `github.com`、`www.github.com`、`codeload.github.com`、`raw.githubusercontent.com`、
  `objects.githubusercontent.com`、`release-assets.githubusercontent.com` 改写，其它链接不动

```bash
# 先查有哪些加速项
curl -s -H "X-Api-Token: $TOKEN" http://127.0.0.1:17890/api/v1/config | jq .mirrors

# 本次任务走 gh-proxy.com
curl -X POST http://127.0.0.1:17890/api/v1/tasks   -H "X-Api-Token: $TOKEN" -H "Content-Type: application/json"   -d '{"url":"https://github.com/o/r/releases/download/v1/a.zip","githubMirrorId":"ghproxy"}'

# 本次任务强制直连（即使客户端设了加速）
curl -X POST http://127.0.0.1:17890/api/v1/tasks   -H "X-Api-Token: $TOKEN" -H "Content-Type: application/json"   -d '{"url":"https://github.com/o/r/releases/download/v1/a.zip","githubMirror":""}'
```

实测（2026-10-30）：指定 `ghproxy` 后任务 URL 变成
`https://gh-proxy.com/https://raw.githubusercontent.com/...`；传空串保持原链接；
不存在的 id 返回 400 `mirror_not_found` 并列出可用项。

`POST /api/v1/config/speed` → 至少给一个字段：

```json
{"maxDownloadLimit":2097152}          // 2 MB/s
{"maxUploadLimit":524288}             // 512 KB/s
{"lowestSpeedLimit":10240}            // 低于 10 KB/s 判失败
```

返回 `{"ok":true,"applied":{...}}`。

注意：**全局限速会同时约束所有任务**，任务级限速在它之下再生效。单位统一是字节/秒。

## 8. MCP

同一端口，路径 `POST /mcp`，JSON-RPC 2.0，鉴权方式相同。支持 `initialize` / `ping` / `tools/list` / `tools/call`；通知类消息（无 `id`）返回 **202** 空体。

协议版本回 `2024-11-05`。

### 工具

| 工具 | 参数 | 对应 REST |
|---|---|---|
| `get_server_status` | 无 | `GET /ping` |
| `list_downloads` | `status?` | `GET /tasks` |
| `get_download` | `gid` | `GET /tasks/{gid}` |
| `create_download` | 同第 3 节字段 | `POST /tasks` |
| `control_download` | `gid`, `action`(`pause`\|`resume`\|`remove`) | 三个 POST |

返回体是标准 MCP 结构：`{"content":[{"type":"text","text":"<JSON 字符串>"}],"isError":false}`。

### 客户端配置

```json
{"mcpServers":{"tinyaii":{
  "type":"http",
  "url":"http://127.0.0.1:17890/mcp",
  "headers":{"X-Api-Token":"<token>"}
}}}
```

只支持 HTTP 传输的客户端才能用（Claude Code、Cursor 等）。Claude Desktop 只认 stdio，**接不进来**——stdio 薄壳方案已经砍掉（不想为它多带一个 exe）。

## 9. 已知限制（都还没做）

| 限制 | 说明 |
|---|---|
| 不解析网盘链接 | 夸克/哔哩等必须先在客户端里解析，API 只收直链 |
| 不收种子文件 | `torrentFiles` 没开放给 API，传了会 400 |
| 配置只读 | 下载目录、并发数只能用客户端界面改 |
| 删除不删文件 | `remove` 只清任务记录，磁盘上的文件保留 |
| 没有推送 | 没做 SSE/WebSocket，要实时进度只能轮询 `/tasks` |
| 没有限流和审计 | 本机 API，没做请求频率限制，也没记调用日志 |
| 时间字段是内存态 | 见第 6 节 |

## 10. 一次性验证脚本

```bash
TOKEN=$(cat "$APPDATA/com.xiaojie.tauri-app/api-token")
B=http://127.0.0.1:17890/api/v1

curl -s -H "X-Api-Token: $TOKEN" $B/ping
curl -s -H "X-Api-Token: $TOKEN" $B/config

# 建任务（限速 500KB/s，校验 sha-256）
curl -s -X POST -H "X-Api-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/a.bin","dir":"D:/下载","maxDownloadLimit":512000}' $B/tasks

curl -s -H "X-Api-Token: $TOKEN" $B/tasks
# 拿上面返回的 id 替换 <gid>
curl -s -X POST -H "X-Api-Token: $TOKEN" $B/tasks/<gid>/pause
curl -s -X POST -H "X-Api-Token: $TOKEN" $B/tasks/<gid>/resume
curl -s -X POST -H "X-Api-Token: $TOKEN" $B/tasks/<gid>/remove
```
